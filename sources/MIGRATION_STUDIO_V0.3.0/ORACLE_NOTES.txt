ORACLE C# V0.3 — observations HTTP indépendantes du calcul mathématique

API gelée
generate_cases() -> 25 cas fermés du MODEL_CONTRACT, 922 instances de questions, au plus 50 questions par quiz. Les 18 premiers lots couvrent chacun des 427 profils de comptes sous les deux barèmes : 413 multiples et 14 uniques. Puis contrôles de seuils voisins de 100/7, seuils 0/100, somme de 7 fractions 1/7, permutation d'ordre et correction masquée. Ce corpus n'énumère pas toutes les chaînes d'identifiants, toutes les séquences HTTP ni tous les états du site.
case_sha256(case) : SHA256 du JSON UTF8 canonique, clés triées, séparateurs compacts, ensure_ascii=False et ordre des listes conservé. Identique à json.dumps(...,sort_keys=True,separators=(',',':'),ensure_ascii=False) pour ce domaine fermé.
collect_cases(cases,output_dir) -> rapport status COLLECTED, REFUSED ou INCONCLUSIVE ; results avec index, case_sha256, status OBSERVED, observed, identité quiz/tentative et résultat C# brut. COLLECTED signifie observations obtenues et contrôles de collecte satisfaits, pas équivalence déjà démontrée.
observed_projection(result,case) projette le résultat modèle/Rust vers score_display,percent_display,passed,correct_count,points[{display,is_correct}]. points=null lorsque show_correction=false. Comparer cette projection à results[i].observed. Les fractions internes C# ne sont pas observées par HTTP ; ne pas leur attribuer les numérateurs/dénominateurs du modèle. La comparaison des fractions exactes Python/Rust est séparée.

Probes de fiabilité de la référence C#
Page Razor réellement rendue par GET /. Chaque cas utilise un nouveau quiz, une nouvelle tentative et un requestId unique. Le premier quiz est modifié après le début de tentative ; le résultat doit conserver son snapshot. Complete est rejoué avec ancienne revision ; après archivage du quiz, Start est rejoué avec la même clé et doit rendre exactement la tentative terminée. Les scores doivent contenir une seule entrée par tentative. Ces probes ne revendiquent aucune migration de ces transitions vers Rust.
Instance de processus conservée avant start() : même un échec READY passe par stop() dans finally. Seul le processus créé est arrêté ; aucun autre serveur utilisateur n'est touché. Le reçu confirme sa sortie, sans réattribuer un ancien état du navigateur. Après arrêt, une source devenue illisible produit INCONCLUSIVE avec raison explicite ; échanges et rapport restent écrits si le dossier de preuves est encore accessible. Cela ne garantit pas une écriture sur un disque inaccessible.
Bornes : 64 cas, 50 questions par cas,2..8 options, IDs 1..80, selected 1..8, réponse HTTP 2 Mo ; délais HTTP 10 s, READY 25 s, arrêt 5 s puis kill 5 s. Budget de 240 s vérifié avant chaque appel HTTP ; il ne constitue pas un watchdog OS sur une lecture disque bloquée. Le coordinateur conserve ses limites globales.
