# QCM — personnalisation et audits du 20 novembre 2026

Cette mise à jour publie les sources du Studio local : images des questions et réponses, disposition par blocs, règles de jeu, aperçu, import/export et préférences des joueurs. Elle comprend les correctifs fonctionnels et de sécurité validés localement. Aucun compte API ni service de modèle payant n'est nécessaire.

## Lancer les sources sous Windows

Installer le SDK .NET 10 à jour (pas seulement le runtime), puis ouvrir PowerShell dans ce dossier `SYNTHESE_MATHS_CODE_V0.2.0` :

```powershell
dotnet publish ./qcm_studio/QcmDemo.csproj -c Release -o ./build-qcm
if ($LASTEXITCODE -ne 0) { throw 'Compilation échouée' }
$env:ASPNETCORE_ENVIRONMENT = 'Production'
$env:MIA_QCM_PORT = '5187'
$env:MIA_QCM_DATA_DIR = Join-Path (Get-Location) 'local/qcm-studio'
dotnet ./build-qcm/QcmDemo.dll
```

Ouvrir ensuite http://127.0.0.1:5187 et garder la console ouverte. `Ctrl+C` arrête le serveur. Les sauvegardes restent dans `local/qcm-studio` ; conserver ce dossier lors des mises à jour. Le port doit être libre. Le fichier historique `Data/questions.json` déjà présent dans le dépôt n'est pas utilisé par le Studio actuel et n'a pas été remplacé par des données personnelles.

Le lanceur Python `launch_site.py` et `mvc_runtime.py` sont également actualisés, mais dépendent d'un SDK local qualifié et de son manifeste, absents de cette distribution. Utiliser la procédure .NET ci-dessus sur une nouvelle machine. Les anciens ZIP de la publication du 15 novembre ne sont pas actualisés par ce commit.

## Corrections

- Caches de brouillons et réponses malformés : restauration sans plantage, conservation du contenu brut avant remplacement.
- Créations de QCM et brouillons : reçus atomiques pour éviter les doublons lors d'une réponse réseau perdue, respect des suppressions et modifications ultérieures.
- Images : édition du texte alternatif sans perdre le contrôle actif, centrage correct, erreurs de transfert compréhensibles.
- Lanceur : récupération après un reçu de compilation invalide ; origine stable pour retrouver les préférences après redémarrage.
- Sécurité : protections HTTP et anti-encadrement par un site tiers, contrôles hôte/port/origine, politique de contenu stricte compatible avec la carte.
- Dimensions des images contrôlées avant décodage ; PNG animés refusés. Imports hostiles, références externes et empreintes falsifiées refusés dans les cas testés.

## Validation et limites

Deux revues indépendantes par phase ont conclu favorablement sur les sources finales. Campagne fonctionnelle : compilation Release, 73 contrôles d'intégration et 40 contrôles navigateur, plus 28 tests ciblés. Campagne sécurité finale : 53 contrôles d'intégration et 26 contrôles navigateur, avec fichiers PNG/JPEG/WebP ; 11 tests ciblés de sécurité également réussis. Les preuves détaillées et sauvegardes des essais restent locales pour éviter de publier des données de travail. Six contrôles ont confirmé la préservation des données et de la carte.

Ces résultats portent sur les scénarios exécutés, pas sur toutes les attaques possibles. Application locale mono-compte : pas de séparation sécurisée entre éditeur et joueur, ni modification des permissions Windows ou chiffrement des sauvegardes. Les anciens caches de navigateur sur un port variable ne sont pas automatiquement migrés. Si le stockage du navigateur est indisponible, un reçu conservé en mémoire ne survit pas à la fermeture de l'onglet. Un import interrompu peut laisser des médias inutilisés. Aucun audit exhaustif des décodeurs natifs ni essai prolongé de saturation n'est revendiqué.
